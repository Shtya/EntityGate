## 2) الـ Big Idea

**الإطار ثابت، والشغل في حفرة.** السايد بار والهيدر سطح واحد فاتح على شكل حرف L، والصفحة في "بئر" أغمق منه، والكروت طافية جوه البئر. أي حد يفهم الترتيب من أول نظرة: إطار، ثم حفرة، ثم ورق فوقها. الزجاج محجوز للي بيطير فوق التلاتة بس.

```
Desktop (≥1024)                          Mobile (<768)
┌────────┬────────────────────────┐      ┌────────────────────┐
│ Logo   │ Search        🌐 🌙 👤 │      │ ☰ ▣       🔍 🌐 🌙 👤│
│        ╭────────────────────────┤      ├────────────────────┤
│ Nav    │ PageHeader            ║│      │ PageHeader         │
│        │ ┌────────────────────┐║│      │ ┌────────────────┐ │
│ Nav    │ │ Card               │║│      │ │ Card           │ │
│        │ └────────────────────┘║│      │ └────────────────┘ │
│        │ ┌────────────────────┐ │      │ ┌────────────────┐ │
│        │ │ Table              │ │      │ │ Table  ←→      │ │
│        │ │▔▔▔▔▔ hbar ▔▔▔▔▔▔▔▔│ │      │ │ Pager (sticky) │ │
```

### العمق: 3 خيارات بسطر واحد

بدّل `data-depth` في [layout.tsx](../src/app/layout.tsx): `<html data-depth="a|b|c">`

| | A: ناعم جدًا | **B: متوسط ✅** | C: جريء |
|---|---|---|---|
| Inset البئر | 2 طبقات، حتى 6px blur | 3 طبقات، حتى 32px | 3 طبقات، حتى 48px |
| ظل الكارت | 1px خفيف | 8px بـ 8% | 20px بـ 16% |
| الإحساس | Stripe | Linear | Dashboard جريء |

**الترشيح: B.** العمق واضح من أول نظرة من غير ما حد يسأل "إيه الظل ده"، وA بيضيع على الشاشات الضعيفة، وC بيشد العين بعيد عن الأرقام.

الظلال كلها بتتضرب في `--dir`، فبتتعكس لوحدها في RTL، وفي `--sa` (1 في الفاتح، 3 في الداكن) عشان العمق يتقرأ بنفس الدرجة.

### الأبعاد
| | القيمة | السبب |
|---|---|---|
| `--header-h` | 56px | نفس ارتفاع صف اللوجو، فمتحاذيين |
| `--sidebar-w` | 248px | 16 + 216 + 16 |
| `--sidebar-rail` | 72px | 16 + 40 + 16 |

**مفيش grain ولا dot grid.** جربت أبررهم ملقتش سبب وظيفي، والبئر بيوصل فكرته من غيرهم. الاستثناء الوحيد: أقواس الـ Sign In، لأنها بوابة اللوجو، ولأن الزجاج محتاج حاجة وراه عشان يبان إنه زجاج.

## 5) Motion Spec

| العنصر | التريجر | المدة | الـ Easing | الخاصية |
|---|---|---|---|---|
| البئر + بداية الهيدر | فتح/قفل السايد بار | 280ms | `cubic-bezier(.22,1,.36,1)` | `transform` |
| نصوص السايد بار | فتح/قفل | 180ms | نفس المنحنى | `opacity` |
| Drawer الموبايل | فتح/قفل | 280ms | نفس المنحنى | `transform` |
| ظل الهيدر | سكرول > 2px | 180ms | ease | `opacity` |
| دخول الكروت | أول تحميل للصفحة | 420ms + stagger 50ms | نفس المنحنى | `opacity` + `transform` |
| Popover / Dialog | فتح | 180ms | `cubic-bezier(.2,0,0,1)` | `opacity` + `transform` |
| Sheet | فتح | 280ms | نفس المنحنى | `transform` |
| Sign In: خطأ | فشل الدخول | 360ms | `cubic-bezier(.2,0,0,1)` | `transform` |

**تفصيلة السايد بار:** الـ layout بيتغير مرة واحدة في البداية، وبعدها بيتحرك البئر بـ `transform` بس (FLIP)، فمفيش relayout في كل frame حتى مع جداول كبيرة. بما إن السايد بار نفس لون الإطار، الحركة الوحيدة اللي بتتشاف هي حافة البئر.

**استثناءات من "transform و opacity فقط":** ألوان الـ hover (`background-color`) و`box-shadow` في الـ pager، لأنهم تغييرات صغيرة ومش بيعملوا layout.

كله بيقف مع `prefers-reduced-motion`.

## 6) Responsive و RTL

| العرض | السايد بار | البئر | Padding | ملاحظات |
|---|---|---|---|---|
| **360** | Drawer | من الحافة للحافة، radius 0 | 16px | البحث أيقونة بس، والجدول بيتحرك جوه الكارت |
| **768** | Rail ثابت 72px، والزرار بيفتح overlay | زاوية 20px | 18.8px | الأيقونات ليها tooltips |
| **1024** | كامل 248px، وينفع يتصغّر | زاوية 20px | 20.7px | |
| **1280** | كامل | زاوية 20px | 22.6px | |
| **1536** | كامل | زاوية 20px | 24.5px | |
| **1920+** | كامل | المحتوى 1600px في النص | 27.4px | 145px من الجهتين |

**RTL:**
- Logical properties بس، وفيه **test بيفشّل الـ build** لو حد كتب `ml-` أو `left-`.
- السايد بار والزاوية والظل والـ scrollbar بيتعكسوا من غير أي كود خاص.
- الـ chevrons بتتقلب بـ `rtl:-scale-x-100`.
- الأكواد والإيميلات جوه `<bdi>`، فمش بتتلخبط وسط النص العربي.
- Instrument Serif مفيهوش عربي، فالعناوين بتستخدم IBM Plex، ومفيش italic.

| الحالة | النتيجة | إزاي اتأكدت |
|---|---|---|
| LTR / RTL | ✅ | قياس + screenshots، والمفتاح بيقلب من غير reload |

| محتوى طويل | ✅ | النص بيتقص عند 216px، والعنوان الطويل بيلف |
| صفحة فاضية | ✅ | Empty state |

| شاشة 1920+ | ✅ | 145 / 145px |
| Dark mode | ✅ | البئر أغمق من الإطار |
| Keyboard focus | ✅ | focus ring، والـ Select والـ picker بالكيبورد |
| Contrast | ✅ | كل مستويات النص ≥ 4.5 في الوضعين (الـ accent الكبير ≥ 3) |
| Firefox / Safari / موبايل حقيقي | ❌ **مااتجربش** | محتاج جهاز حقيقي |

**Bugs لقيتها أثناء الفحص واتصلحت:**
1. الـ focus كان بيزحزح الإطار كله لجنب (`overflow: hidden` ← `clip`)، وفي Sign In كمان.
2. الـ Select بيظهر فاضي لحظة عند التحميل.
3. مسافات غير متساوية (29 / 17) تحت 1024.
4. عنوان الترحيب العربي كان صغير جدًا.
5. فاصلة عربية ظاهرة في النص الإنجليزي.
6. `faint` على البئر كان 3.96، أقل من AA.

**نقد الـ Art Director:** كل مسافة ليها منطق؟ أيوه، كلها مشتقة من `--page-pad`. العمق مفهوم؟ أيوه. بيتطبق على كل الصفحات؟ أيوه، من الـ layout. اللي مش راضي عنه: الـ active item في الـ rail بيتقص عند حافة البئر، وده مقبول لأنه شبه tab، بس عايز مراجعة عينك.

## 9) تقرير النقاط 2–6

### i18n
[next-intl](../src/i18n/request.ts) بـ cookie، و[en.json](../messages/en.json) و[ar.json](../messages/ar.json) فيهم نفس المفاتيح، وفيه test بيتأكد من ده ومن إن مفيش قيمة عربية ناقصة. أخطاء الـ API نفسها مترجمة حسب لغة المستخدم.

**افتراض مهم:** التواريخ ميلادية والأرقام لاتينية في العربي. `ar-SA` لوحده بيطلّع هجري، وده كان هيبقى كارثة في الفواتير.

### Theme
Light هو الـ default، والاختيار بيتحفظ، ومفيش flash عند التحميل.

### Authentication
- صفحة Sign In زجاجية: validation، loading، error بهزة خفيفة، إظهار/إخفاء الباسورد.
- `admin@gmail.com` / `123456` من الـ env، والـ seed **بيرفض يشتغل في production**.
- الباسوردات **argon2id** (اتغيرت من scrypt)، وفيه test.

### Components
Native `<select>` و`<input type="date">` ممنوعين بـ ESLint وبـ test. الـ Select بيتحول لـ combobox بالبحث تلقائيًا فوق 7 خيارات. الـ DatePicker مبني على react-day-picker بالعربي والإنجليزي.

### System Audit

**مشاكل أمان لقيتها وصلحتها:**
| المشكلة | الخطورة | الإصلاح |
|---|---|---|
| Open redirect في `?next=/\evil.com` | عالية | [safe-next.ts](../src/lib/safe-next.ts) + test |
| الأدوار read-only (Executive, Auditor) كانوا يقدروا يرفعوا ملفات | متوسطة | صلاحية على الرفع + test |
| مفيش CSP | متوسطة | Nonce لكل request في [middleware.ts](../src/middleware.ts) + test |
| مسارات Better Auth المباشرة بتتخطى الـ audit (`/update-user`, `/change-password`...) | متوسطة | اتعطلت + test |
| `Origin: null` بيعمل crash 500 | منخفضة | بقى 403 + test |
| تاريخ مستحيل (`2026-02-30`) بيعمل 500 | منخفضة | بقى 422 + test |
| رسائل الـ DB كانت بتكشف أسماء الأعمدة | منخفضة | رسالة عامة |

**SQL Injection:** مفيش raw SQL غير `SELECT 1` ثابت، وESLint بيمنع النسخ الـ unsafe. **XSS:** مفيش HTML من المستخدم، والـ CSP طبقة تانية.

**سلامة الـ DB** ([migration](../prisma/migrations)):
- 34 index ناقص على الـ foreign keys.
- مفيش راتبين أو rate cardين متداخلين لنفس الموظف/العقد.
- `total = subtotal + VAT` مفروضة على مستوى الـ DB.
- التحصيل مايقدرش يتعدى قيمة الفاتورة أو الدفعة، حتى مع عمليتين في نفس اللحظة (trigger بـ row lock).
- Billing run واحد حي لكل شهر.

**الحسابات المالية:** [finance.ts](../src/lib/finance.ts) مع [الـ tests بتاعته](../tests/unit/finance.test.ts): الفواتير، الـ proration، النقل وسط الشهر (بيطلع مظبوط للهللة)، الـ aging، والـ P&L.

### ⚠️ مهم تعرفه
- **الفواتير والمدفوعات والـ P&L لسه مالهاش شاشات ولا API**، لأنهم M5 وM6. اللي اتعمل هو المعادلات والـ tests وقيود الـ DB. يعني "الـ transactions في العمليات المالية" لسه هتتكتب مع الـ modules دي.
- `finance.ts` مبني على تعريفات لسه محتاجة تأكيد من Finance (Q1, Q2, Q4).
- تشفير الإقامة والجواز لسه M2.
- فحص الفيروسات مااتجربش فعليًا، وDocker والـ CI عمرهم ما اشتغلوا.

### قرارات محتاجها منك
1. **`admin@gmail.com` عنوان حقيقي ممكن يبقى لشخص تاني.** لما الإيميلات تشتغل في M3، أي تنبيه هيروح له. اقتراحي `admin@entitygate.test`.
2. **تجاوز الـ 2FA:** ضفت `AUTH_MFA_ENFORCED=false` عشان تدخل بـ admin على طول. بيتجاهل في production دايمًا. لو عايز 2FA حتى محليًا امسحه من `.env`.
3. **الأرقام في العربي:** لاتينية (`1,234`) ولا هندية (`١٬٢٣٤`)؟ استخدمت اللاتينية لأنها الشائعة في الفواتير السعودية.
